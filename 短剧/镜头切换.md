## 一句话机制

**上一镜尾的情绪节拍决定下一镜头的入场方式。** 三类切点对应三种转场：缓切 / 硬切 / 接切。

## 切点机制（节拍 → 转场）

| 上一镜尾节拍 | 下一镜头入场 | 转场类型 |
|---|---|---|
| 期待 / 留白 | 平视、慢推 | 缓切 |
| 紧张 | 跳视、急推 | 硬切 |
| 释放 / 收束 | 视线接力、动作接力 | 接切 |

节拍值取自 `情绪节拍库.md`。

## 转场类型（3 类）

### 1. 情绪匹配 → 缓切

**适用**：相邻两镜头节拍相同或递进（如期待→期待、紧张→紧张）。
**写法**：下一镜头第一句描述"延续上一镜的情绪氛围"，运镜速度与上一镜尾一致。

### 2. 动作接续 → 硬切

**适用**：上一镜尾是具体动作，下一镜头从动作中途切入。
**写法**：下一镜头的【演员动作】段首句直接描述该动作的延续（不要重复上一镜头的动作过程）。

### 3. 视线接力 → 接切

**适用**：上一镜尾有明确视线方向，下一镜头从该方向入画。
**写法**：上一镜头最后描述视线方向（看向画面左/右/上方）；下一镜头第一句描述"从该方向入画"或"从该方向走出"。

## 与现有工程的关系

切点机制是**写作提示**——落在 `创意MV/NNN.txt` 的【镜头 N】段开头一句，不在工程代码层强制实现。

节拍判定依赖 `情绪节拍库.md`；形象一致性依赖 `形象指纹.md`；剧情节奏依赖 `剧本层.md`。

## 反向说明（不做什么）

- ❌ 不做硬切/缓切的自动检测——判定权在写作时的人/AI
- ❌ 不规定转场必须配乐——配乐是另一层问题
- ❌ 不写"万能转场公式"——三类转场已穷尽常见情况，但不强制组合
- ❌ 不替用户决定节奏——5 镜 3 类转场怎么分布由剧本决定

## 配套脚本

本机制的 Python 实现位于 `../scripts/`：

- `drama_schema.py` — DramaConfig / Character / Shot dataclass 强类型校验
- `drama_yaml.py` — 最简 YAML 1.2 子集 frontmatter 解析器
- `drama-new.py` — 建短剧工程骨架（自增编号）
- `drama-shot.py` — 单镜头文件生成（指纹 + 节拍 + 转场自动注入）
- `drama-from-json.py` — JSON 主导端到端桥接（核心入口）
- `drama-lint.py` — 跨镜头一致性 + 节拍 / 转场 / frontmatter 检查（CHECKS 注册表）
- `drama-find.py` — 按 tag / type / applicable 检索短剧 markdown

AI 使用 markdown 时，配合 `python3 scripts/drama-find.py --tag transition` 检索相关文件，不必全文 Read。
